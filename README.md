# Recruitment Funnel Doctor

Агент для конкурса Поток AI Agent Challenge. Работает поверх открытого API
«Потока» и решает две задачи рекрутера:

1. **Диагностика воронки** — сам находит проблемные вакансии, сравнивает их
   со здоровыми, строит ранжированные гипотезы о причинах (LLM) и оставляет
   след в самом Потоке — комментарий с диагнозом и напоминание рекрутеру.
2. **Подготовка к интервью** — по конкретному кандидату читает вакансию и всю
   историю взаимодействий, честно отмечает, какие компетенции уже
   подтверждены/под вопросом, и готовит вопросы под пробелы — материал для
   интервьюера, не готовое решение о найме.

Есть CLI (`main.py`, `seed.py`) и веб-интерфейс на Streamlit
(`streamlit_app.py`) в стилистике самого Потока.

## Быстрый старт (если вы никогда не пользовались Python)

Пошагово, для Windows. Если что-то не заработало на каком-то шаге — не
пропускайте его, каждый следующий шаг зависит от предыдущего.

**1. Установите Python.**
Зайдите на https://www.python.org/downloads/, нажмите жёлтую кнопку
«Download Python» и запустите скачанный файл. **Важно:** на первом экране
установщика обязательно поставьте галочку **«Add python.exe to PATH»** внизу
окна — без неё дальнейшие команды не будут работать. Дальше просто
«Install Now» и дождитесь окончания.

**2. Скачайте код проекта.**
Откройте страницу репозитория на GitHub, нажмите зелёную кнопку **«Code»** →
**«Download ZIP»**. Распакуйте скачанный архив в любую папку, например
`C:\funnel_doctor`.

**3. Откройте терминал в этой папке.**
В Проводнике Windows зайдите в распакованную папку (там, где лежит файл
`README.md`), в адресной строке сверху введите `powershell` и нажмите Enter —
откроется синее окно терминала уже в нужной папке.

**4. Проверьте, что Python установился.** Введите в терминале:
```powershell
python --version
```
Должно вывести что-то вроде `Python 3.12.x`. Если написано «python не
является внутренней или внешней командой» — значит галочку из шага 1 не
поставили; переустановите Python ещё раз, не забыв про неё.

**5. Установите зависимости проекта** (библиотеки, без которых код не
запустится) — одна команда, выполнится за минуту-две:
```powershell
pip install -r requirements.txt
```

**6. Получите два ключа, без которых агент не сможет работать:**
- **Токен Потока** — в вашей компании в Потоке: Настройки → Генерация
  токенов.
- **Ключ Anthropic** — зарегистрируйтесь на https://console.anthropic.com,
  раздел API Keys → Create Key. Понадобится привязать способ оплаты
  (расход на этот проект копеечный — центы за прогон).

**7. Впишите ключи в конфигурацию.** В папке проекта есть два файла-образца.
Скопируйте каждый (можно прямо в Проводнике: выделить файл → Ctrl+C →
Ctrl+V → переименовать копию) и впишите в копии свои значения:
- `.env.example` → скопировать и переименовать в `.env`
- `.streamlit\secrets.toml.example` → скопировать и переименовать в
  `.streamlit\secrets.toml`

Или той же командой в терминале:
```powershell
Copy-Item .env.example .env
Copy-Item .streamlit\secrets.toml.example .streamlit\secrets.toml
```
Откройте оба новых файла блокнотом и замените `your-...` на свои реальные
значения (`POTOK_BASE_URL`, `POTOK_TOKEN`, `ANTHROPIC_API_KEY`). В
`secrets.toml` также придумайте свой `APP_PASSWORD` — это пароль для входа
в веб-интерфейс.

**8. Заполните тестовыми данными** (если в вашем Потоке ещё нет вакансий с
историей — агенту не на чем будет ничего показать):
```powershell
python -m funnel_doctor.seed init
python -m funnel_doctor.seed add-background
python -m funnel_doctor.seed seed-healthy-demo
python -m funnel_doctor.seed tick
```
Каждая команда что-то напечатает в терминал и завершится — это нормально,
дожидайтесь появления новой строки-приглашения перед следующей командой.

**9. Запустите веб-интерфейс:**
```powershell
streamlit run funnel_doctor/streamlit_app.py
```
Через несколько секунд в браузере сама откроется страница
`http://localhost:8501` — введите пароль из `APP_PASSWORD` и пользуйтесь.
Чтобы остановить — вернитесь в окно терминала и нажмите `Ctrl+C`.

Подробности, что делает каждая команда, и запуск без графического
интерфейса (через командную строку) — в разделах ниже.

## Как это устроено

1. **`api.py` / `potok_client.py`** — тонкий клиент к API v2/v3 «Потока»:
   auth, пагинация (постраничная и курсорная), backoff на 429.
2. **`metrics.py`** — считает то, чего нет в самом API: конверсию, среднее
   время на этапе, среднюю задержку ответа рекрутера после смены этапа,
   разбивку причин отказа (см. «Расхождения с документацией» ниже), плюс
   дешёвую эвристику health-статуса для дашборда (`quick_snapshot`, без
   похода в events).
3. **`hypotheses.py`** — отдаёт посчитанные метрики (не сырой доступ к API)
   модели Claude и просит вернуть ранжированные гипотезы + конкретную
   рекомендацию, через tool-use для надёжного структурированного ответа.
4. **`interview_prep.py`** — то же самое tool-use-разделение (Python считает
   факты, LLM интерпретирует) для подготовки к интервью: вакансия + профиль
   кандидата + история событий → статус по компетенциям + вопросы.
5. **`actions.py`** — публикует диагноз обратно в Поток: комментарии на
   активных кандидатах проблемной вакансии (`POST /api/v2/events`) и
   напоминание ответственному рекрутеру (`POST /api/v3/calendar/reminders`).
   Никаких автоматических decline/move — решение остаётся за человеком.
6. **`streamlit_app.py` / `theme.py`** — веб-интерфейс: Дашборд (карточки
   вакансий с health-бейджем), Вакансия (метрики + воронка), Исследование воронок
   (сравнение + гипотезы + кнопка «Применить»), Подготовка к интервью.
7. **`seed.py`** — генератор демо-данных, см. ниже.

### Почему сравнение "вакансия vs вакансия", а не "период vs период"

В API нельзя явно проставить `created_at` при создании сущностей — все
таймстемпы server-side. Значит данные, засеянные одним прогоном, не дают
осмысленной истории по времени. Поэтому «Исследование воронок» сравнивает две
похожие вакансии между собой в моменте (кросс-секционно) — это работает
с первого дня и не зависит от того, сколько реальных дней прошло с посева.

### Расхождения с документацией API, найденные на реальном тенанте

- Тип события в `POST /api/v2/events` должен быть `"Event::Comment"`
  (namespaced), а не `"comment"`, как в примере из `05-events.md`.
- Системное событие смены этапа называется `"Event::Stage"`, а не
  `"Event::StageChanged"`.
- В ответе `GET /jobs/:id/ajs_joins` нет полей `declined_at` и
  `declination_reason_id`, задокументированных в `04-ajs-joins.md` — момент
  и причина отказа берутся из события `Event::Decline` (поле
  `properties.declination_reason_id`).

## Установка

Требуется Python 3.10+.

```bash
pip install -r requirements.txt

# для CLI (main.py, seed.py) — переменные окружения из .env
cp .env.example .env
# заполнить POTOK_BASE_URL, POTOK_TOKEN, ANTHROPIC_API_KEY

# для веб-интерфейса (streamlit_app.py) — отдельный файл секретов Streamlit
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
# заполнить те же значения + APP_PASSWORD (пароль для входа в интерфейс)
```

`POTOK_TOKEN` — токен вашей компании в Потоке (Настройки → Генерация
токенов). `ANTHROPIC_API_KEY` — ключ с console.anthropic.com, нужен для
работы LLM-гипотез и подготовки к интервью.

## Демо-данные

Настоящих исторических данных в тестовом тенанте может не быть — `seed.py`
создаёт демо-вакансии и постепенно проводит по ним синтетических кандидатов
через реальные вызовы API.

```bash
python -m funnel_doctor.seed init                     # один раз — здоровая/больная вакансия + план
python -m funnel_doctor.seed add-background            # один раз — ещё вакансии для дашборда
python -m funnel_doctor.seed seed-healthy-demo          # один раз — контрольная явно здоровая вакансия
python -m funnel_doctor.seed tick                       # запускать ежедневно (cron/Планировщик) до демо
python -m funnel_doctor.seed status                     # посмотреть прогресс сценария
python -m funnel_doctor.seed fast-forward <job_key> [N] # разово: N кандидатов сразу до конца воронки, без растяжки по дням
```

Каждый `tick` выполняет те шаги плана, чей срок наступил, — так у кандидатов
в Потоке появляются настоящие, растянутые по времени `stage_changed_at` и
`created_at`, а не пачка событий с одной датой.

## Запуск веб-интерфейса

```bash
streamlit run funnel_doctor/streamlit_app.py
```

Секреты (`POTOK_BASE_URL`, `POTOK_TOKEN`, `ANTHROPIC_API_KEY`, `APP_PASSWORD`)
берутся из `.streamlit/secrets.toml` (см. `.streamlit/secrets.toml.example`).
`APP_PASSWORD` защищает интерфейс при публичном хостинге — кнопка
«Применить» пишет в реальный Поток.

## Запуск через CLI

```bash
# метрики по одной вакансии
python -m funnel_doctor.main report --job-id 12345

# полное исследование: метрики + сравнение + гипотезы Claude
python -m funnel_doctor.main investigate --job-id 12345 --baseline-job-id 12346

# то же самое, но с публикацией находки обратно в Поток
python -m funnel_doctor.main investigate --job-id 12345 --baseline-job-id 12346 --apply
```

Без `--job-id`/`--baseline-job-id` `investigate` подставит вакансии из
`seed_state.json`, если сценарий уже инициализирован.

## Известные ограничения MVP

- «Подготовка к интервью» не парсит содержимое резюме (PDF) — работает по
  структурированным полям кандидата и истории комментариев/событий в Потоке.
  Если история пустая, честно помечает компетенции как «нет данных», а не
  выдумывает.
- Оценка кандидата **после** интервью (надиктовка рекрутера → структурированный
  скоринг по компетенциям) из идеи не реализована — сознательно отложена,
  чтобы уложиться в срок; текущая версия закрывает только подготовку.
- Задержка ответа рекрутера считается по `events` конкретного кандидата —
  при большом числе кандидатов на вакансии это N+1 запросов; для MVP
  (десятки кандидатов) укладывается в rate limit 100 req/10s, для вакансий
  с сотнями кандидатов потребуется батчинг через `events_stream` с фильтром
  по периоду вместо обхода по каждому applicant_id.
- Ответы Claude в tool-use не всегда строго следуют схеме (иногда весь объект
  приходит JSON-строкой в одном поле, иногда часть полей просто отсутствует) —
  `hypotheses.py` и `interview_prep.py` содержат защитный разбор на этот
  случай, но при смене модели стоит перепроверить.
